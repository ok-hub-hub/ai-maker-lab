## なぜポートフォリオが「合否を分ける」のか

未経験者が書類選考を通るための武器は実質2つだけです。①志望動機、②ポートフォリオ。資格や学歴がない分、**「自分が実際に何かを作れる」ことを示すものが必要**です。

採用担当がポートフォリオに求めるのは、以下の3点です。

1. **動くこと**：README 通りに動くか確認される（動かないと選考終了）
2. **何を解決しようとしたか**：「誰のどんな困りごとをITで解決した？」を説明できるか
3. **コードが読めるか**：コメント、命名、ファイル構成から「チームで働ける人か」が判断される

「すごいアプリ」は必要ありません。シンプルでも、**ストーリーが語れること**が最優先です。

## AIツールを使ったポートフォリオ作成：5ステップ

### STEP 1：テーマと「解く問題」を1文で書く

例：「友人への誕生日プレゼント候補をLINEで相談すると、AIが3案を返すWebアプリ」

この1文が書けないと、コーディングを始めても途中で迷子になります。AIに「自分の日常の困りごと×Webアプリ」を壁打ちしてもらうのが効率的です。

### STEP 2：技術スタックを固定する（広げすぎない）

未経験で最もよくある失敗は、「React + TypeScript + Next.js + Prisma + Docker + AWS」を全部やろうとして完成しないことです。

**おすすめの現実的スタック（1本目）**

| ジャンル | 選択肢 |
|---------|--------|
| フロントエンド | HTML/CSS/JavaScript（シンプルに）または React |
| バックエンド | Node.js（Express）または Rails（Rubyに慣れているなら）|
| DB | PostgreSQL または SQLite |
| デプロイ | Render / Railway（無料枠で動く）|

### STEP 3：AIで「骨格」を作ってから理解する

Claude や v0 を使ってコンポーネントの骨格を生成し、**1行ずつ何をしているか確認しながら進める**のが2026年の現実的な学習法です。

注意：AIが出力したコードをそのまま貼り付けるだけでは、面接で「このコードについて説明してください」と聞かれたときに答えられません。**「動く → 読む → 理解する」の順序**を守ることが重要です。

### STEP 4：GitHub に公開し README を書く

採用担当が最初に見るのは README です。以下の要素を入れてください。

```markdown
## プロジェクト名
## 概要（誰のどんな課題を解決するか 2〜3行）
## 使用技術
## 機能一覧
## セットアップ手順（ローカルで動かす方法）
## 工夫したこと・苦労したこと（←ここが最重要）
```

「工夫したこと・苦労したこと」は2〜3つ、具体的に書きます。「初めてAPIを叩く処理を書いたとき、非同期処理の順序でエラーが出て解決に3日かかった。原因はPromiseの返し方を誤解していたこと」レベルの粒度が理想的です。

### STEP 5：デプロイして URL を作る

「ローカルでしか動かない」ポートフォリオは採用担当が触れません。**Render や Railway の無料枠でデプロイ**し、動作確認用の URL を GitHub の README に貼りましょう（確認時点で無料枠のスリープがある場合はその旨を README に書く）。

## 何を作るか：採用担当の目に止まるテーマ選び

「ありきたりすぎる」と思われがちな題材でも、ストーリー次第で差が出ます。テーマ選びのポイントは**「自分が実際に困ったこと」から出発する**こと。

| テーマ例 | なぜ有効か |
|---------|-----------|
| 家計管理アプリ | CRUD・認証・グラフ表示を一通りカバー |
| 読書記録 × AIおすすめ | AI API の呼び出しを含む、時代感がある |
| チームのシフト管理 | 前職・バイト経験と結びつけた説明ができる |
| 飲食店の在庫管理 | 「業種知識 + IT」で独自性が出る |

**避けるべきテーマ**：TodoアプリをそのままGitHubにあげるだけ（独自の改造や説明がなければ選考通過は厳しい）。

## GitHub公開とREADME：最低限のライン

GitHub を公開する前のチェックリストです。

- [ ] `.env` ファイル（APIキー・パスワード）が `.gitignore` に入っているか
- [ ] README に概要・技術スタック・セットアップ方法があるか
- [ ] コミットメッセージが `fix typo`・`asdfgh` のような意味不明なものばかりでないか
- [ ] デプロイ先URLが機能しているか（スリープ明けでも動くか）
- [ ] main/master ブランチ以外に feature ブランチの使い分けがわかるか（あれば加点）

## よくある落とし穴

**1. 「完成したら応募しよう」で完成しない**

ポートフォリオに終わりはありません。まず MVP（最小限動くもの）を完成させて応募し、フィードバックをもらいながら改善する、というサイクルが現実的です。

**2. スタックを広げすぎて全部中途半端になる**

1本目のポートフォリオでは、技術の幅より「1本ちゃんと動かせた」実績が評価されます。

**3. ポートフォリオを作っただけで転職活動を始めない**

作ること自体が目的化してしまうケースがあります。ポートフォリオは手段です。ある程度の形になったら転職エージェントに見せ、「このレベルで応募できる求人はあるか」を聞くのが時間を無駄にしない方法です。

## FAQ

**Q. TODO アプリでも転職できる？**  
A. テーマ自体は問題ありません。重要なのは、「なぜこのアプリを作ったか」「どこで詰まり、どう解決したか」を自分の言葉で説明できるかどうかです。TODO アプリでも語れれば通る、技術的なものでも説明できなければ落ちます。

**Q. AIが書いたコードを使っても OK？**  
A. 構造を理解した上で使うなら問題ありません。ただし、面接で「このコードについて教えてください」「なぜこの書き方にしたんですか」と聞かれるため、説明できない部分を残しておくのはリスクです。AIは足場を作るツール、理解する責任は自分にある、という姿勢で使いましょう。

**Q. どのくらいの期間で作れる？**  
A. 1本目のポートフォリオなら、毎日2〜3時間確保できれば4〜8週間が目安です。技術スタックの絞り方・AIツールの活用度・完成ラインの設定によって大きく変わります。

**Q. 複数のポートフォリオは必要？**  
A. まず1本を「ちゃんと動いて説明できる状態」にするのが先です。応募を始めてからフィードバックをもとに2本目を作る方が、時間を有効に使えます。

**Q. スクールの料金は？**  
A. ポテパンキャンプ・忍者CODEともに、**相談・カウンセリングは無料、受講は有料**です。料金はコースやプランにより異なり、変更になる場合もあるため、最新情報は必ず各公式サイトでご確認ください（本記事では料金を断定しません。2026-10-19 時点で公式を確認することを推奨します）。

**Q. 地方在住でも使えるサービスはある？**  
A. ポテパンキャンプ・忍者CODEはオンライン完結のため、地方でも受講できます。転職エージェントは首都圏求人が中心のため、地方在住の場合は求人数が制限される可能性があります。
