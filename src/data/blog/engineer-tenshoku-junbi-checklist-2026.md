「**転職しようと思っているけど、まず何から準備すればいい？**」

ITエンジニアの転職市場は求人数が多い反面、「準備不足で面接に進んでしまって失敗した」という声も少なくありません。本記事では、**転職活動を動き出す前に揃えておくべき7ステップ**を、順番ごとに整理します。

## 30秒で結論：準備の全体像

| ステップ | やること | 目安時間 |
|---|---|---|
| **1 棚卸し** | スキル・実務経歴を書き出す | 1〜2時間 |
| **2 軸を決める** | 「次に何をしたいか」を1文にまとめる | 1〜2時間 |
| **3 職務経歴書（初稿）** | まず60〜70点の初稿を作る | 半日〜1日 |
| **4 ポートフォリオ** | フロント・バックエンド系は必要、インフラ系は状況次第 | 数日〜2週間 |
| **5 エージェント相談** | 準備の方向を確認してもらう（無料・在職中可） | 1時間 |
| **6 書類ブラッシュアップ** | エージェントのフィードバック込みで仕上げる | 半日 |
| **7 面接対策** | テーマ別に答えを用意する | 1週間〜 |

**ポイント：** ステップ5（エージェント相談）は書類が完成してからでなく、**初稿段階で入れる**のが効率的です。プロの目線で「何を強調すべきか」が分かると、書き直しが1回で済みます。

## STEP 1：現状の棚卸し（スキル・業務経歴）

「自分のスキルは分かっている」と思っていても、採用担当者の視点で整理するとかなり変わります。棚卸しで出すのは次の4点です。

1. **使用技術・ツール**（言語、フレームワーク、クラウド、DB）
2. **担当フェーズ**（要件定義／設計／実装／テスト／運用保守）
3. **チーム規模・役割**（メンバー / リード / プロジェクトマネジャー）
4. **成果を数値化できるものがあるか**（処理速度X%改善、リリース〇本）

数値が出せる成果が1つでもあると、書類・面接の印象が大きく変わります。

---

## STEP 2：「次に何をしたいか」を言語化する

面接で必ず聞かれるのが「なぜ転職するのか」と「次に何をやりたいか」です。

曖昧なまま動き出すと、軸がブレて選考で落ちやすくなります。以下の問いに答えを書き出してみてください。

- 現職で満足していること／不満なことは何か？
- 5年後にどんな仕事をしていたいか？
- 年収・勤務形態・技術スタックの優先順位は？

これを1〜2文にまとめたものが「転職軸」になります。エージェントや書類・面接でも使いまわせます。

---

## STEP 3：職務経歴書の初稿を作る

まず「完璧でなくていい60〜70点の初稿」を作ることが大事です。完璧を目指して書き始めると、手が止まります。

### 職務経歴書のテンプレ構成

```
1. 職務要約（3〜5文）
2. 職歴（会社名・期間・担当プロジェクト・使用技術・成果）
3. スキルシート（言語・FW・クラウド・ツールを表形式で）
4. 自己PR（転職軸と紐づけた強みを3〜5行）
```

### よくある失敗

- **「〜を担当しました」で終わっている**：何をどう解決したかが伝わらない
- **スキルシートが羅列になっている**：「触ったことある」と「実務で使った」は別物
- **ボリュームが多すぎる**：経験年数にもよりますが、A4で2〜3枚が目安

初稿を書いたら、次のステップでエージェントに見てもらうのが最速の改善法です。

---

## STEP 4：ポートフォリオを用意する（必要な人だけ）

ポートフォリオが必要かどうかは職種次第です。

| 職種 | ポートフォリオの必要性 |
|---|---|
| フロントエンド / モバイル | **必要**（見た目の品質が直接評価される） |
| バックエンド（Webサービス） | **あると強い**（実動するAPIやOSS貢献が評価される） |
| インフラ / SRE / 運用 | **なくてもOKが多い**（実績・資格で代替） |
| PM / テックリード | **設計資料・アーキ図があると強い** |

### 最低限のライン

- GitHub リポジトリに実際に動くコードがある
- README に「何のためのツールか」「使用技術」が書いてある
- ホスティングされていて動作確認できる（Vercel / Railway 等）

完璧なポートフォリオよりも、「実際に動いていて、考えたことが分かる」ものの方が評価されます。

---

## STEP 5：エージェントに「まず相談」する

書類の初稿ができた段階で、エージェントに相談するのが効率的です。

転職エージェントのメリット：

- 書類のフィードバックが**無料**でもらえる
- 「今の自分のスペックでどの企業・年収帯を狙えるか」が分かる
- 非公開求人（エージェント経由のみ）にアクセスできる
- 在職中でも相談から始められる

**転職エージェントは求職者への料金は発生しません**（採用企業側から報酬を得るビジネスモデルのため）。「まだ転職を決めていない」段階での相談も可能です。

> エージェントはあくまで紹介・支援サービスです。相談・紹介サービスであり、転職や年収の結果を保証するものではありません。また、経歴・希望エリアにより紹介できる求人が限られる場合があります。

---

## STEP 6：応募書類を面接前提でブラッシュアップ

エージェントからのフィードバックを受けて書類を仕上げます。

- 成果・数値の表現が面接で話しやすい構成になっているか
- 自己PRが転職軸と一致しているか
- スキルシートに「年数・習熟度」が添えられているか

この段階で **志望企業リストと照らし合わせ**、企業ごとに「強調すべき経験」を入れ替えるだけで合格率が変わります。

---

## STEP 7：面接対策をテーマ別に分けて準備する

面接の準備をまとめて「練習しておく」ではなく、**テーマ別に答えを準備**するのが効率的です。

### テーマ別チェックリスト

| テーマ | 代表的な質問 |
|---|---|
| **転職理由** | なぜ今の会社を辞めるのか（ネガティブにならず） |
| **自己PR** | 自分の強みと実績を2〜3分で話せるか |
| **技術力の深堀り** | 「〇〇を使った理由」「課題とどう解決したか」 |
| **志望動機** | なぜこの会社に応募したのか |
| **逆質問** | 入社後に活躍できるか確認するような質問を1〜2問 |

面接は「いい人材かどうか」よりも「この会社で活躍できそうか」を判断される場です。実績を語るときは「WHY（なぜその判断をしたか）」まで伝えられると評価が変わります。

## FAQ

**Q. 在職中でも転職準備を始められる？**
A. 完全にオンラインで完結するため、在職中でも問題ありません。平日夜・週末での面談に対応しているエージェントが多いです。

**Q. 書類が完成していない段階でエージェントに相談してもいい？**
A. 大丈夫です。初稿の段階で相談すると「何を強調すればいいか」のフィードバックをもらえるため、書き直しが最小で済みます。

**Q. 転職エージェントは本当に無料？**
A. 求職者への費用は発生しません。エージェントは採用が成立した企業側から報酬を得るモデルのため、相談・書類作成・面接対策のサポートはすべて無料です。ただし、相談サービスであり転職の成功や年収を保証するものではありません。

**Q. 複数のエージェントに同時登録してもいい？**
A. 一般的には問題ありません。エージェントごとに保有求人が異なり、複数に登録することで選択肢が広がります。ただし、並行管理の手間を考えると2〜3社が現実的です。

**Q. AIスキルを転職でどうPRするか？**
A. 具体的な成果に紐づけて伝えるのがポイントです。「ChatGPTを使った」ではなく「ChatGPT APIを組み込んで、〇〇業務をX時間→Y時間に短縮した」のように、**業務課題とその結果**をセットで伝えられると評価されやすくなります。

## まとめ

ITエンジニア転職の準備は「書類 → エージェント相談 → ブラッシュアップ → 面接対策」の順で積み上げるのが最短ルートです。

- **まず初稿（60点でOK）を作り、エージェントに見てもらう**
- **転職軸を1〜2文で言語化しておく**と、書類・面接両方に使える
- **エージェントへの相談は書類完成前でも無料・オンライン可**

「まだ転職を決めていない」段階での相談も歓迎されています。準備の方向が合っているかを確認するだけでも、動いてみる価値があります。
